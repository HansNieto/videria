Instala Videria una vez en cada computadora. Después abre el icono Videria y elige el proyecto. No necesitas abrir PowerShell, arrancar servidores, instalar Python ni copiar la app cada vez que edites.

1. Instalar la app — los dos hacen lo mismo

  1. Entra con tu cuenta a GitHub → Videria → última versión. Si el repositorio es privado, Hans debe invitar a MaykNE a videria y a videos.
  2. En Assets, descarga Videria-2.4.0-Windows-x64.zip (o la versión más reciente). No el archivo “Source code”: ese ZIP no contiene la aplicación compilada.
  3. Clic derecho al ZIP → Extraer todo. Abre la carpeta extraída. Deben estar Instalar-Videria.cmd, Instalar-Videria.ps1 y la carpeta Videria.
  4. Haz doble clic en Instalar-Videria.cmd. Se instala para tu usuario, sin pedir administrador, y crea el acceso directo Videria en el Escritorio y en Inicio.
  5. Abre Videria. Verás tu lista de proyectos. Mantén íntegra la carpeta instalada: el EXE depende de _internal, no lo copies solo.
El ejecutable todavía no tiene firma de un editor comercial. Si Windows muestra una advertencia, verifica que descargaste exactamente la versión de HansNieto/videria y, si tienes dudas, compara su SHA-256 con el archivo publicado. No desactives el antivirus ni la protección de Windows.

Incluye Python, FFmpeg, fuentes y stickers. Si falta el motor de ventana, instala Microsoft Edge WebView2 Runtime (Evergreen x64) desde Microsoft y vuelve a abrir. Para sincronizar proyectos instala también GitHub Desktop e inicia sesión.

2. Hans: abrir las preediciones 17, 18, 19 y 20

La app busca automáticamente el repositorio de proyectos en C:\Users\Hans\Documents\videria2.0\videos. Cada carpeta interna aparece como video17-proyecto, video18-proyecto, etc. Pulsa Editar.

Si no aparece alguno, pulsa Agregar carpeta y selecciona:

C:\Users\Hans\Documents\videria2.0\videos
Selecciona la carpeta -proyecto, que contiene project.json y timeline.json; no la carpeta video17 que contiene las grabaciones. No vuelvas a clonar estos videos encima de tu edición local ni reemplaces local.json: conecta el proyecto con tus originales.

Dentro del editor, Proyectos guarda los cambios antes de volver a la lista. Puedes cambiar al 18, 19 o 20 desde ahí. Guarda también con Ctrl+S antes de cerrar la app.

3. MaykNE: instalar y recibir los videos privados

  1. Hans te agrega como colaborador en los dos repositorios privados: HansNieto/videria para instalar la app y HansNieto/videos para editar. Acepta ambas invitaciones.
  2. Instala Videria siguiendo la sección 1. Abre GitHub Desktop e inicia sesión como MaykNE.
  3. En GitHub Desktop: File → Clone repository → URL. Pega https://github.com/HansNieto/videos y clónalo una sola vez.
  4. En Videria 2.4: Agregar carpeta → elige la raíz videos. La app detectará todos sus proyectos. También puedes usar Descargar proyectos de GitHub y pegar el mismo enlace.

El único repositorio de edición es HansNieto/videos. Nunca pegues claves en la app ni las subas al repositorio.

No necesitas claves de Google o Pexels para editar. Los recursos de la preedición ya viajan con el proyecto. La previsualización del revisor usa proxies livianos; no confundas su calidad con la del render final de Hans.

4. Qué hace cada uno por video

Hans prepara y entrega

  1. Conserva las grabaciones originales fuera del repositorio videos. La preedición y la generación de recursos se hacen en tu computadora.
  2. Abre la preedición en Videria, revísala y guarda con Ctrl+S.
  3. En GitHub Desktop selecciona HansNieto/videos. Revisa solo la carpeta del proyecto trabajado → escribe “Preedición lista · video 21” → Commit to main → Push origin.
  4. Avisa a MaykNE y no edites ese mismo proyecto mientras él lo revisa.

MaykNE corrige y devuelve

  1. Con Videria cerrada, GitHub Desktop → HansNieto/videos → Fetch origin → Pull origin.
  2. Videria → proyecto → Editar. Corrige cortes, subtítulos, posiciones, recursos y sonido.
  3. Importa imágenes, audio o video con el botón Importar o arrastrándolos al editor. Quedan dentro de la carpeta del proyecto.
  4. Guarda con Ctrl+S. En GitHub Desktop confirma que los cambios pertenecen al proyecto correcto → mensaje FINAL · revisión creativa video17 → Commit to main → Push origin.

Hans recibe y renderiza

  1. Con el proyecto cerrado, recibe los cambios con Fetch/Pull origin en GitHub Desktop. También puedes usar Recibir cambios en Videria si Git ya está autenticado.
  2. Si hay cambios locales pendientes, primero revísalos y publícalos; Videria bloquea el pull para no pisar tu trabajo. No uses “Discard all changes” a ciegas.
  3. Videria → Editar → Renderizar. El final usa los originales conectados mediante local.json. El botón Borrador sirve para revisar una exportación ligera.
  4. Al terminar, pulsa Abrir carpeta. El MP4 aparece en carpeta-del-proyecto\exports. Los MP4 finales no se suben al repo del proyecto.
GitHub transporta los proyectos en videos; la app se instala desde Releases de videria. Aunque haya varios proyectos en un repo, trabajen cada proyecto por turnos: un mismo timeline.json no se fusiona de forma fiable.

5. Cuando actualizamos la app

  1. Los dos guardan y cierran Videria.
  2. Entran a Actualizar app en la pantalla de inicio o a Releases y descargan el nuevo ZIP.
  3. Extraen todo y ejecutan Instalar-Videria.cmd otra vez. El acceso directo apunta a la nueva versión.
  4. Abren el mismo icono y el mismo proyecto. No vuelven a generar la preedición, no reemplazan originales, no clonan los proyectos de nuevo y no necesitan hacer git pull del código de la app.

La instalación está en %LOCALAPPDATA%\Programs\Videria\app-VERSION. El código fuente vive en videria; los proyectos viven en videos. No es una actualización automática: ambos deben instalar el nuevo paquete.

6. Color original, GPU y exportación en 2.3.0

Renderizar ahora abre un cuadro de opciones. Para tus videos verticales, empieza con 1080p (1080 × 1920), 30 FPS, calidad equilibrada y codificador automático. También puedes elegir 720p/1440p/4K, hasta 60 FPS y audio AAC. Más FPS no crea movimiento que no se haya grabado. Estas opciones no cambian el lienzo editable.

Color original es la opción predeterminada: no hay corrección automática ni conversión HDR → SDR. Tus grabaciones HLG se exportan como HEVC de 10 bits, conservando HLG/BT.2020. Los ajustes manuales activados sí se aplican. SDR compatible convierte HDR solo si lo eliges expresamente; no lo elijas si quieres conservar el perfil original. Si mezclas cámaras con perfiles distintos, debes elegir una salida compatible explícitamente.

Para ajustar un clip, selecciónalo y baja hasta Color · ajustes manuales. Cada barra tiene una casilla donde escribir el número. Valores neutros: brillo 0, contraste 1, saturación 1, temperatura 0, viñeta 0. Desmarca aplicar ajustes para comparar sin perder los valores o pulsa Restablecer color para dejarlos neutros. Ctrl+Z deshace. Los ajustes ya guardados en tus proyectos no se borran al actualizar.

La casilla Original reproduce directamente la cámara, sin el proxy convertido de la versión anterior. HDR/HEVC requiere soporte del navegador, reproductor y pantalla. La apariencia puede variar en una pantalla SDR o con HDR de Windows apagado. La vista de ajustes manuales es orientativa. El archivo editado se vuelve a comprimir y no conserva los metadatos dinámicos Dolby Vision; sí conserva su base HLG compatible. El original de cámara nunca se modifica.

Automático prueba NVIDIA NVENC y lo usa si está disponible; si no, usa CPU y lo informa. La exportación muestra hevc_nvenc/h264_nvenc cuando usa GPU. La app incluye FFmpeg 8.0.1 compatible con el controlador 595.79 de la RTX 4060 probada. No cambia tus controladores. Capas, subtítulos y ciertos efectos siguen en CPU: mira GPU → Video Encode en el Administrador de tareas, no solo el gráfico 3D. Una prueba de 4 s de HLG sin efectos tardó 3,87 s en CPU y 1,59 s en GPU (~2,4×); no es una garantía para montajes con efectos pesados.

Si MaykNE solo tiene proxies antiguos, la calidad y el color están limitados por esos archivos. El indicador dirá «Proxy (color aproximado)». Activar Original no recupera colores que ya se convirtieron dentro del proxy. El final debe renderizarse desde los originales en la computadora de Hans. Los MP4 anteriores no cambian: vuelve a renderizar; la app crea otro nombre si ya existe.
  • Mover: arrastra un clip a izquierda o derecha. Los demás permanecen donde estaban; puedes dejar huecos.
  • Superponer: suelta encima de otro elemento de la misma pista. Se crea una capa nueva. Los videos de arriba se ven delante y sus audios se mezclan: silencia el clip que no quieras escuchar en el inspector.
  • Alinear: acerca el inicio o el final a otro borde o al cabezal. La guía azul indica el ajuste magnético. Mantén Alt para ignorarlo, o usa el imán / M.
  • Capas: mueve objetos verticalmente entre pistas del mismo tipo; usa ▲/▼ para cambiar su orden. Texto y recursos visuales van sobre el grupo de video. El botón ＋▱ también permite añadir pistas vacías de video, texto, imagen o audio.
  • Subtítulos: su pista sigue protegida contra textos encimados. Para títulos superpuestos usa una capa de texto independiente.
  • Guardar y deshacer: Ctrl+S guarda las posiciones y capas; Ctrl+Z revierte un movimiento. Los originales nunca se recortan físicamente.
Los dos deben instalar 2.2.0 o posterior antes de intercambiar proyectos con pistas de video superpuestas. Las versiones antiguas no interpretan estas posiciones libres. No uses el editor clásico “cortes” para reorganizar un montaje multipista.

La línea de tiempo mantiene las mejoras de 2.2.0. Motor incluido: FFmpeg 8.0.1, build de Gyan.

7. Si algo falla

  • Todos los botones parecen muertos: cierra la ventana antigua y abre la app actualizada.
  • GitHub muestra 404: inicia sesión con la cuenta invitada y acepta la invitación del repo correcto.
  • Recursos ausentes: confirma que se descargaron assets y broll; no copies solo los JSON.
  • El render final pide originales: renderiza en la computadora de Hans; MaykNE puede exportar borradores.
  • La app no abre: comprueba WebView2 y %LOCALAPPDATA%\VideriaData\app.log. Envía el log sin credenciales.
  • Desinstalar: cierra Videria y elimina solo su carpeta de instalación y accesos directos; conserva proyectos, originales y VideriaData.
